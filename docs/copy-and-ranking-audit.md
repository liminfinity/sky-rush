Дополнительное раскрытие содержит честное ограничение демо-билетов и округление. Убраны DTO/сервер/снимки конфигурации и неверное утверждение о симулированных соперниках. Проверка исхода доступна через «Ещё → Проверка полёта», а не занимает место на результате. Админка сохраняет точные сообщения о валидации полей; её устаревшая надпись «без авторизации» исправлена.

Неизвестные ответы API и исключения больше не выводятся игроку как сырой backend message. Игрок получает короткую русскую ошибку; evaluator-форма по-прежнему показывает точные ошибки CONFIG_VALIDATION/CONFLICT/WRITE_FAILED.

## Откуда брались ненастоящие соперники

В текущем Java-коде нет генератора ботов: CompetitionService выбирает зарегистрированные аккаунты из PostgreSQL и суммирует их реальные earned_points за UTC-день. Flyway не сидирует Alice/Bob. При старте создаётся только настоящий evaluator demo. Во frontend были устаревшая ветка `simulated` и ложный текст Правил; они удалены. Из DTO удалено всегда ложное поле `simulated`.

В основной базе оставались **16 аккаунтов прошлых моих проверок**: 15 Alice/Bob из E2E и один Tunnel test из публичного auth smoke. Их происхождение подтверждено предыдущими запусками, временем создания и форматом логинов, созданных конкретными тестами; удаление выполнено по закрытому списку **UUID + точный логин**, без запросов DELETE по имени/префиксу. Перед удалением сохранён приватный pg_dump вне репозитория: `/tmp/skyrush-before-fixture-cleanup.dump`.

В одной транзакции удалены только зависимые записи этих 16 аккаунтов. Для остальных пользователей SQL сравнил полные снимки строк users/wallets/reward_progress/game_rounds/wallet_entries/ticket_offers до и после удаления: изменений нет. **Сохранены demo и все три обычных зарегистрированных аккаунта.** Данные demo, в том числе заработанные им очки, не сбрасывались. Удаляющей миграции или очистки по маскам при старте нет. См. результат транзакции (local verification artifact).

Один человек — одна строка. Нулевые очки не скрывают аккаунт, но не дают место на подиуме. Подиум показывает до трёх реальных участников с положительным счётом; остальные — в списке. Текущий игрок выделен один раз, без дубля вверху и внизу. Никаких заполнителей свободных мест. Порядок/очки приходят из API; существующий polling не менялся.

## Чтобы тестовые игроки не возвращались

```sh
cd frontend
npm run test:e2e
```

Команда запускает `scripts/run-e2e.sh`: уникальный Compose project, отдельный volume PostgreSQL, случайный локальный порт nginx, временная копия game-demo.yml и конфигурации билетов. Перед браузерами проверяется demo-only seed. По окончании, при ошибке и Ctrl+C удаляются только ресурсы этого проекта. Основная база и конфигурация не используются. Прямой Playwright без маркера изоляции отклоняется. Тесты используют настоящую регистрацию и настоящий сервер, без подставных игровых ответов.

После аварийного SIGKILL/выключения машины trap не выполняется: удалять можно только оставшийся проект `skyrush-e2e-...` и его volume, проверив имя. Не удаляйте volume обычного `sky-rush`.
