# Seven-minute judge walkthrough

This is a transparent deterministic rehearsal preset, not normal randomness. Announce that distinction. It changes configuration only; all displayed outcomes still come from the real Java backend. Default `game-config.yml` and unset seed retain SecureRandom and normal rules.

## Prepare before the presentation

1. Follow README to start PostgreSQL. Use a disposable database with a fresh 1000.00 demo wallet, or confirm enough balance with `/api/wallet`. Do not delete a shared database. One presenter/tab controls the shared demo identity.
2. From the repository root, after exporting the database variables as in README:

```sh
cp config/game-demo.yml /tmp/skyrush-demo-game.yml
cp config/prototype-config.yml /tmp/skyrush-demo-prototype.yml
export SKYRUSH_CONFIG_PATH=/tmp/skyrush-demo-game.yml
export SKYRUSH_PROTOTYPE_CONFIG_PATH=/tmp/skyrush-demo-prototype.yml
export SKYRUSH_RANDOM_SEED=42
cd backend
./gradlew bootRun
```

3. Start the frontend in a second terminal: `cd frontend`, `npm ci`, `npm run dev`. Defaults are frontend <http://localhost:5173>, backend <http://localhost:8080>, Swagger <http://localhost:8080/swagger-ui.html>. Verify `/actuator/health` is UP.
4. Start this backend process fresh for a reproducible sequence. Finish any saved active round before rehearsal; don't clear localStorage while its flight is active. Restore `points_per_level: 10` in the loaded temporary game file before rehearsing.
5. Log in with **demo / demo12345**. Keep the loaded YAML and Swagger in adjacent tabs. Increase browser zoom if the projector needs it. Open Rules, then close it with Escape to verify keyboard behavior.

The preset gives crash base in `[10,12)`, growth 1 per second and booster level 1 with certainty. Flights last roughly 9–11 seconds. Level 1 arrives at 200 ms; wait for the server-driven enabled button and act within the first few seconds. The seed makes the sample sequence repeat, not your click timestamp. Do not promise an exact payout in a live demo.

For Compose, the backend's config path is fixed to `/app/config/game-config.yml`. To rehearse with Compose, first back up the host `config/game-config.yml` outside the repo, temporarily copy `config/game-demo.yml` over it, and set `SKYRUSH_RANDOM_SEED=42` in your ignored `.env`. Run `docker compose up --build -d`; if already running, recreate backend with `docker compose up -d --force-recreate backend`. Use the UID/GID exports from README so admin can save. Edit **game-config.yml**, not game-demo.yml, for Scenario 5 in this mode. Restore the backup and unset the seed afterwards. Do not submit the rehearsal values as the default.

## Live sequence (target: 5–6 minutes, one minute for questions)

| Time | Action | Say / point out |
| --- | --- | --- |
| 0:00–0:40 | Select a balloon, show 1000.00 bonus balance, switch GREEN/RED, open Rules | RED has 12 levels, GREEN 9. Same crash distribution, different milestones and appearance. Four stakes pair with boosters |
| 0:40–1:20 | RED, TRIPLE, Start; wait for “Активирован”; cash out promptly | Stake debited once, booster level generated by server, ×3 effect and point bonus visible. Fixed payout appears; balloon continues |
| 1:20–1:50 | Wait for win result; accept or decline the simulated ticket offer promptly, then expand/check the outcome commitment | Tickets are imitation only. Two fragments earned. Payout, score and fragments are separate; hash matches the initial commitment |
| 1:50–2:30 | Prepare the loaded YAML editor next to the app. Play Again; select GREEN/BASIC; immediately change points_per_level 10 → 37 and save during flight; do not cash out | The active round keeps 10 points per level. Stake lost at crash, score retained, one fragment |
| 2:30–3:30 | Explain the finished round and saved configuration change | No Java edit or restart. The old snapshot remains verifiable in history; the next round will use 37 points per level |
| 3:30–4:10 | Start another BASIC round, inspect “Каждый уровень: 37 очков”, cross levels, cash out | First crossed level gives 37; a poll after two gives 74. Cashout adds 25. New round snapshot differs; prior results stay unchanged |
| 4:10–4:40 | Wait for result; open History | With a fresh wallet, win/loss/win gives 2+1+2 fragments, converts 5 into 5.00 bonus units. This credit is separate from payout |
| 4:40–5:20 | Close History; open/close Tournament, then wait ten seconds without interaction | Real top three and pinned current player. Result automatically returns to theme selection. Dialogs pause the countdown |
| 5:20–6:00 | Show typed Admin form, Swagger, architecture and math summary | Server authority, exact decimals, row locks, idempotent starts, snapshot reload; tests cover duplicate/concurrent requests |

The time ranges include explanation and transitions, not exact round timing. Combine the configuration edit with the loss flight; if you miss that window, demonstrate it during another active round. Rehearse the edit beforehand.

## Useful recovery paths

- A refresh during an active flight restores it from the saved ID. This is the additional product feature worth demonstrating if time permits.
- If a click loses to crash, show the honest loss, wait for completion and retry; do not alter client state or invent a result.
- A reconnecting banner means the last authoritative state is retained. Check backend health; cashout follows server processing time.
- A 503 after editing YAML means invalid configuration. Undo the edit; active rounds keep valid snapshots. Use [configuration.md](configuration.md).
- If the demo wallet is exhausted, prepare a fresh **disposable** database before the presentation, not an undocumented top-up during it. Restart alone does not refill wallets.
- Restore points to 10, restore default config if copied for Compose, and unset the seed after rehearsal. The preset is not a balanced economy.

## Additional checks outside the seven-minute talk

1. Open **Ещё (⋯) → Настройки игры**, change points per level in the numeric field, and save “Математика и награды”. Start BASIC to see it. An active round keeps its old rule. Restore the value in the same form. The second form independently controls active flag and upsell rules; explain that this requires the demo evaluator login.
2. Complete a qualifying TRIPLE win. After the one-time ticket prompt, select **Повторить ставку**: a distinct round starts under current rules. Cash out, observe no second prompt in this tab session. A new tab session is needed to demonstrate an offer again (or deliberately clear only its sessionStorage as rehearsal setup).
3. Refresh an active flight; then remove only `skyrush.session.v1.<account UUID>` from localStorage and refresh again. The server active-discovery endpoint restores the authenticated user's flight. Do not clear the pending request record during an uncertain start.
4. In a new tab session let a qualifying ticket offer expire. Bonus balance stays unchanged. Accept a later offer in a fresh session and show persisted ticket count. Do not describe simulated tickets as lottery participation.
5. Retain the initial `integrity.commitment`; after crash hash the exact revealed payload. Legacy pre-V3 history correctly has no integrity proof.
6. Prepare a later booster by temporarily shifting weights away from level 1; cash out early and observe MISSED. Restore the rehearsal config afterwards.

The automated E2E suite (`npm run test:e2e`) creates its own disposable Compose project and copies the demo configuration. It never uses the shared demo database; test users, rounds and config changes are removed with that project on exit. Sound is optional and off by default; do not rely on projector audio for explaining gameplay.
