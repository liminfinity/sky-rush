# Достижения, задание дня и реальные игроки

## Достижения

В профиле появился компактный раскрывающийся раздел «Достижения». Всего 11 постоянных отметок:

| ID | Название | Условие |
|---|---|---|
| FIRST_FLIGHT | Первый полёт | Завершён первый полёт |
| FIRST_WIN | Есть! | Завершён полёт с cashout |
| RISK_TAKER | Рискнул | Cashout ≥ ×3 |
| HIGH_FLYER | Выше облаков | Уровень ≥ 8 по умолчанию |
| BOOSTER_HUNTER | Поймал бустер | Активирован любой бустер |
| BOOSTER_X4 | На максимум | Активирован ×4 |
| WIN_STREAK_3 | Серия | 3 победы подряд |
| WIN_STREAK_5 | Хладнокровие | 5 побед подряд |
| BIG_WIN | Крупный выигрыш | Выплата ≥ 200 по умолчанию |
| VETERAN_25 | Налетал | 25 завершённых полётов |
| VETERAN_100 | Сто полётов | 100 завершённых полётов |

Сервер проверяет сохранённую историю после завершения полёта. Серии используют порядок `completed_at, id`. Ранее заработанные результаты тоже учитываются при следующем завершённом полёте; миграция не создаёт фиктивных открытий. Открытие сохраняется один раз и не отнимается при смене настроек. Короткое уведомление показывается только на результате, а не во время полёта.

Достижения **без валютных наград**: только статус. Они не меняют шансы, выплаты, бустеры, очки или фрагменты.

## Одно задание на UTC-день

Все игроки получают одно и то же задание. Индекс — `floorMod(UTC_DATE.toEpochDay(), 7)` в следующем фиксированном порядке:

1. PLAY_ROUNDS — завершить 3 полёта.
2. WIN_ROUNDS — завершить 2 полёта с cashout.
3. EARN_POINTS — получить 150 очков.
4. ACTIVATE_BOOSTER — активировать любой бустер.
5. ACTIVATE_X3_OR_HIGHER — активировать ×3 или ×4.
6. REACH_LEVEL — достигнуть уровня 6.
7. CASHOUT_ABOVE — забрать на ×2,5 или выше.

Порог сохраняется в общей строке даты при первом обращении. Смена настроек не переписывает уже выбранное задание этого дня. В 00:00 UTC GET автоматически возвращает следующее задание; внешний планировщик не нужен.

Прогресс обновляется **при завершении полёта**, по его серверному `completed_at` (времени взрыва). Полёт через полночь относится к дню завершения. Поздняя обработка после перезапуска сохраняет эту дату. Для уровня и cashout берётся максимум; для остальных — сумма подходящих действий/очков, ограниченная целью. Неудачный cashout не считается победой.

Награда — **ровно +1 Sky Fragment**, автоматически, без кнопки получения. Запись `(user, date)` хранит прогресс, завершение, награду и исходный полёт; уникальный `daily_round_contributions.round_id` не даёт обработать один полёт повторно. Изменения проходят в транзакции завершения под существующей блокировкой пользователя.

Дополнительный фрагмент сразу входит в накопительную коллекцию и добавляется к остатку фрагментов. Прежняя формула обмена не менялась: если он довёл остаток до порога, обмен выполнится при **следующем завершённом полёте**. Выплата уже завершённого полёта не меняется. Личные `totalFragments` теперь включают и обычные награды, и задания дня; `Round.reward` остаётся наградой самого полёта.

## Онлайн

Видимая авторизованная вкладка отправляет heartbeat примерно раз в 25 секунд. Сервер считает уникальные аккаунты, у которых heartbeat был за последние 90 секунд. Несколько вкладок/устройств одного аккаунта не увеличивают число. Записи чаще раза в 20 секунд сервер пропускает.

Это **недавняя активность**, а не точный статус соединения: закрывший вкладку или вышедший игрок может оставаться в счётчике до конца окна. Скрытые вкладки не отправляют heartbeat. IP, session ID и прочие служебные данные не публикуются.

## Сейчас в игре

Лента содержит только сохранённые сервером события:

- успешный cashout с зафиксированным множителем;
- первая активация бустера в полёте;
- одно наиболее позднее по каталогу новое достижение за завершённый полёт, даже если открыто несколько.

События создаются внутри транзакции реального действия; уникальный ключ `roundId:eventType` предотвращает дубли. Читаются последние 5 за час, в порядке `created_at DESC, id DESC`. При отсутствии событий — «Пока тихо». Хранилище остаётся обычной таблицей, без отдельной системы событий; старые строки пока не удаляются автоматически.

Публикуется **displayName**, а не логин. Как и имена в живом рейтинге, это публичное игровое имя; не стоит использовать в нём личные данные. Лента доступна только авторизованным игрокам.

**Ботов, фиктивных игроков, искусственного онлайна и сгенерированных событий нет.** Начальная БД содержит только аккаунт demo; присутствие, события, достижения и дневной прогресс пусты, пока реальный человек не действует.

## API и частота запросов

- `GET /api/achievements` — свои постоянные достижения.
- `GET /api/daily-challenge` — своё задание текущего UTC-дня.
- `GET /api/activity` — общий счётчик и последние реальные события.
- `POST /api/presence/heartbeat` — пустое тело `{}`, сессия и CSRF.

Нет API для отправки события, открытия достижения, установки прогресса или получения награды за чужого игрока. Поля записи heartbeat, включая userId, отклоняются.

Frontend использует один последовательный цикл с паузой 5 секунд между запросами: activity/heartbeat, затем daily. Интервалы не перекрываются; при скрытии вкладки запросы приостанавливаются, при unmount отменяются. Достижения читаются при входе, открытии профиля и завершении полёта. Игровой poll и рейтинг сохраняют прежнюю частоту.

## Настройки и хранение

`config/social-config.yml` содержит только мета-параметры. После изменения нужен перезапуск backend; существующий hot reload `game-config.yml` не затронут. Путь можно задать через `SKYRUSH_SOCIAL_CONFIG_PATH`. Все значения проверяются при старте:

| Поле | По умолчанию | Диапазон |
|---|---:|---|
| presence-seconds | 90 | 30–300 |
| big-win | 200 | >0 |
| high-level | 8 | 1–9 |
| daily-rounds | 3 | 1–25 |
| daily-wins | 2 | 1–10 |
| daily-points | 150 | 1–10000 |
| daily-level | 6 | 1–9 |
| daily-cashout | 2.5 | 1–10 |

Награда задания фиксирована: 1 фрагмент. Отдельный админ-конструктор достижений не добавлен.

V6 добавляет `user_achievements`, `daily_challenges`, `daily_challenge_progress`, `daily_round_contributions`, `user_presence`, `player_activity_events`. Старые миграции не менялись. Существующие таблицы игры и выплаты не переписываются. Индексы покрывают владельца/дату, уникальность открытий, недавнюю активность и события.

Как и личные рекорды, достижения пока читают небольшую проекцию завершённой истории; для очень больших историй можно перейти к агрегатам. Никаких Redis, Kafka, WebSocket, дополнительных сервисов или планировщиков.
